Factory Inventory Management System

Architecture overview: a Vue 3 single-page application backed by a FastAPI service that serves in-memory data loaded from JSON files. There is no database.

Data flow

How a filter change on any page becomes a re-rendered view. Filter state is a module-level singleton, so every page shares the same four filters.

User changes a filter

FilterBar updates one of four shared refs: period, warehouse, category, order status.

Watcher fires

The view watches the refs (confirmed in Dashboard.vue) and calls its loadData function.

Build the request

getCurrentFilters() maps period to month. api.js drops any value equal to all and issues a GET with query parameters.

Filter in memory

FastAPI runs apply_filters and filter_by_month over the lists loaded by mock_data.py. Quarters such as Q3-2025 expand to three months.

Validate and respond

Core endpoints return through a Pydantic response_model. Dashboard, spending and report endpoints return computed dicts.

Derive and render

Raw responses are stored in refs (allOrders, inventoryItems). Computed properties derive KPIs and chart series, and Vue re-renders.

Observations

Findings from reading the code. Worth knowing before extending the system.

Gap Client calls endpoints the server does not implement api.js defines /tasks (GET, POST, PATCH, DELETE) and /purchase-orders (POST, GET by backlog item). main.py has no such routes, although the PurchaseOrder models exist and purchase_orders.json is loaded. Those calls would return 404. Tasks currently come from the mock user in useAuth.js.
Caveat Filters are not uniformly applied Inventory has no time dimension, so the period filter does not affect it. total_backlog_items in the dashboard summary ignores all filters. Month matching is a substring test on order_date.
Caveat Duplicated quarter logic QUARTER_MAP drives filtering, while /api/reports/quarterly re-implements the same mapping with an if/elif chain. Both are hard-coded to 2025.
Caveat Environment coupling The API base URL is hard-coded in api.js, and CORS allows all origins. Both are acceptable for a local demo but need configuration before any shared deployment.
Note Unrouted view Backlog.vue exists but is not registered in the router; backlog data is surfaced through the Dashboard and BacklogDetailModal.
Strength Simple, consistent patterns One API client, one filter composable, one filter helper pair on the server, and raw-data-in-refs with derived-data-in-computed on the client make the system easy to follow and extend.
